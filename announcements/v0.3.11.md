# reinhardt-web v0.3.11

## Highlights

This release focuses entirely on hardening the migrations and schema-generation pipeline, fixing several correctness issues that could produce incomplete or duplicated DDL — particularly on fresh databases and in repeated `makemigrations` runs.

`makemigrations` now orders `CreateTable` operations by actual foreign-key dependencies instead of lexicographic table names, and initial migrations correctly record cross-app `dependencies` for external table providers. This fixes a real-world failure where applying generated migrations against a fresh PostgreSQL database raised `relation does not exist` errors because referenced tables weren't created first.

Several related fixes restore missing constraint and index metadata that was previously dropped during migration state generation: default indexes on foreign-key columns are now preserved and correctly replayed across repeated runs, field-level `#[field(check = "...")]` constraints are now propagated into generated migrations, and duplicate single-column UNIQUE constraints (one from the field flag, one synthesized) are now collapsed into a single, stably-named constraint. A follow-up fix also corrects quoting for constraint identifiers containing special characters and ensures renamed tables properly recreate their UNIQUE constraints under the new synthesized name, with MySQL-specific backtick quoting applied where appropriate.

Together, these changes make generated migrations more faithful to model definitions and safer to apply against real databases without manual editing.

## Breaking Changes

No breaking changes in this release.
