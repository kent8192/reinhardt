# reinhardt-web v0.3.14

## Highlights

This release introduces opt-in OpenAPI schema generation for DTOs via the new `#[dto(schema)]` attribute. Previously, sharing DTOs between server and wasm clients meant either pulling in the full OpenAPI dependency graph for every DTO or hand-rolling schemas separately. Now, plain `#[dto]` stays lightweight and wasm-friendly, while applications that need native OpenAPI `Schema` generation can explicitly opt in per-DTO. This release also includes several follow-up fixes that round out the feature: correcting qualified `validate` derive recognition, wiring the schema facade completely, and recognizing direct REST schema derives, along with review feedback addressed for the initial implementation.

Authentication also gets a significant upgrade with async session-backed OAuth state support. Applications using `AsyncSessionBackend` previously had to fall back to an in-memory state store for social OAuth flows, which made safe multi-replica deployments difficult and left browser/session binding, expiry, and replay protection as the application's responsibility. This release adds `ContextualStateData`, a contextual `StateStore`, and a new `SocialAuthBackend` flow with built-in protections against login-CSRF, session-swap, provider-swap, replay, and expiry attacks — backed by constant-time SHA-256 validation and atomic state consumption (including Redis `GETDEL` support). Existing `begin_auth`/`handle_callback` call sites remain source-compatible, so this is a drop-in improvement for existing social auth integrations.

Additionally, this release includes routine CI maintenance to keep dependency policy checks green by permitting known, unavoidable duplicate versions of `miniz_oxide` and `pem` in the full-feature dependency graph.

## Breaking Changes

No breaking changes in this release.
