# reinhardt-web v0.3.3

## Highlights

This release focuses heavily on security hardening across the CI pipeline and the ORM/auth layers. The CI auto-fix workflow now uses a fail-closed branch-protection classifier that permits automated style fixes only on branches whose sole active rule is `non-fast-forward`, evaluates eligibility from the trusted PR base commit, and excludes `.auto-fix-policy/**` from any applied patch — closing a path that could otherwise let PR-controlled code widen the write boundary or overwrite trusted policy files.

On the data layer, the explicit-connection queryset path now builds parameterized SQL via `build_select_statement` instead of inlining string literals, eliminating a MySQL SQL-injection risk when filter values contain backslashes. Related fixes ensure UUID-looking filter values are preserved as text, typed temporal filter values are bound correctly, and the admin interface now supports typed filter values consistently with the ORM.

Authentication also receives an important fix: `AuthState::from_extensions` now denies by default when a bare legacy `String`/`Uuid` extension is present without an explicit `IsAuthenticated`/`IsActive` wrapper, preventing unintended authorization. Additionally, `DatabaseSessionBackend::load` and `exists` now route through the connection injected via `from_connection()` rather than the global ORM connection, fixing a bug where sessions could be written to one database and read from another, causing valid logins to appear unauthenticated.

On the developer-experience side, HTTP route handlers can now combine a raw `Request` argument with typed extractors while preserving argument order, giving handlers access to request metadata alongside extracted values. Several CI dependency-policy adjustments (allowing `syn` major-version and `base64` duplicates) and the removal of the standalone SemVer Check workflow round out this maintenance release.
