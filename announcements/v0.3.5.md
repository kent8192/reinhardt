# reinhardt-web v0.3.5

## Highlights

This release focuses on stabilizing the gRPC facade for applications using the `reinhardt-web` crate's `grpc` feature with dependency injection. Previously, projects depending on the facade only (rather than importing `reinhardt-grpc` directly) could not use `grpc_handler` with DI enabled, and generated macro code required an unnecessary direct `tracing` dependency. This release resolves macro paths through either direct dependencies or the renamed `reinhardt-web` facade, so DI-enabled gRPC handlers now compile and work correctly regardless of how the facade is imported.

Two related macro-resolution fixes round out the gRPC work: facades that depend on the `reinhardt-grpc` package alone (without additional crate paths) are now correctly supported, and explicit aliases applied to facade imports are now preserved rather than silently overridden during macro expansion. Together these changes make the gRPC macros more robust across the variety of ways a project can wire up its dependencies.

The remaining changes in this release are internal CI/infrastructure improvements — restoring Codecov LCOV report uploads, installing missing WASM tooling for the intra-crate coverage suite, and enabling sccache for faster Rust builds — which do not affect application behavior but improve the reliability of the project's own test and release pipeline.
