# reinhardt-web v0.3.6

## Highlights

This release focuses on correctness and security hardening in the ORM and authentication layers. The most significant fix addresses a class of primary-key binding bugs: the ORM's default `Model::primary_key_filter_value` previously coerced any primary-key value to `i64`, which could cause numeric-looking custom IDs (e.g. `"01"`, `"+1"`, `"0001"`) to be bound as integers and silently return the wrong row on coercive databases. The default now preserves the exact string representation for manual/custom primary-key types, while derived models and explicit overrides continue to supply typed (integer/UUID/timestamp) bindings as before.

Two additional security fixes land in this cycle: the `#[model]` macro now correctly excludes fields marked `#[field(skip_getter = true)]` from generated `{Model}Info` DTOs, closing a leakage path for auth-sensitive fields such as `password_hash` and `is_superuser`. A regression that had silently downgraded `JwtSessionSettings.secret` from `SecretString` to plain `String` — losing zeroization and secret-source redaction — is also restored.

A stricter session-validation change (requiring `CurrentUser<U>` to reject inactive accounts and removing implicit session-derived auth state) was merged as PR #5905 but was reverted later in the same cycle via PR #5910 after being identified as an accidental merge. As a result, session authentication behavior is unchanged from the previous release; see the linked discussion for the proposed (not-yet-shipped) breaking change.

Local infrastructure tooling also gained hardening against tampered `.reinhardt/local-infra.json` state files that could otherwise redirect secrets or authorize removal of arbitrary Docker containers.

## Breaking Changes

- ⚠️ [[reinhardt-web#5905] fix!(auth): require validated account state for sessions](https://github.com/kent8192/reinhardt-web/discussions/5911)

  Note: The underlying change (PR #5905) was reverted by PR #5910 within this release cycle, so this breaking change is **not** included in v0.3.6. The discussion remains open for future consideration.
