# reinhardt-web v0.3.7

## Highlights

This release focuses on two important security fixes. The first restores the correct behavior of the `#[field(skip_getter = true)]` macro attribute: a recent regression had stopped excluding these fields from generated `{Model}Info` DTOs, which could leak sensitive values such as password hashes, API keys, and internal flags during serialization, and could enable mass-assignment through DTO-to-Model conversions. This release reinstates the exclusion and clarifies the distinction between `skip_getter` and `skip_info` in the macro documentation.

The second fix addresses a regression in `SessionMiddleware` that derived authentication and admin/active state directly from a stored `USER_ID_SESSION_KEY`, without revalidating against the current database user record. This allowed stale sessions to continue granting access even after an account was deactivated. Authorization decisions are now re-anchored to the current database user state, with a restored account-validating middleware pattern and updated tutorial examples demonstrating the correct approach.

Additionally, this release records the RUSTSEC-2026-0249 advisory for the unmaintained `smartstring` transitive dependency in `cargo-deny` configuration, since no patched release is currently available, keeping the security audit gate green while remediation continues to be tracked separately.

The bulk of the remaining PRs in this release are internal test-coverage improvements across many crates (DI, dentdelion, db, testkit, forms, mail, pages, shortcuts, streaming, i18n, commands, providers, storages) along with CI/CD fixes to coverage reporting and UI test isolation. These do not change user-facing behavior but improve the project's regression-testing safety net.
