# reinhardt-web v0.4.0-alpha.12

## Highlights

This release introduces opt-in DTO schema generation for macros, giving downstream crates a way to derive request/response schemas directly from their DTOs without requiring changes to existing derive setups. Several follow-up fixes round out the feature: the schema facade wiring is completed, qualified `validate` derives are now matched correctly, direct REST schema derives are recognized, and DTO schema target gating is preserved so the macro only activates where intended. Review feedback on the initial schema implementation has also been addressed, improving correctness and consistency across the macro expansion.

Building on the DTO ecosystem, PR #6200 adds a new `#[client_form(...)]` attribute macro that generates the existing client-form companion API directly from a DTO. This gives users a more concise alternative to the previous combination of `#[derive(ClientForm)]` plus a separate helper attribute, while fully preserving the legacy API for backward compatibility. The change is covered by a runtime-backed UI fixture and documented alongside the existing ClientForm derive.

On the maintenance side, `develop/0.4.0` has been synchronized with `main` (PR #6206), bringing in async OAuth state handling, middleware session updates, feature-matrix and dependency-policy improvements, and disabling an unused rcgen PEM feature to keep the dependency graph compliant. A CI fix (PR #6207) also unblocks the dependency-policy security audit by explicitly allowing the currently unavoidable `pem` and `miniz_oxide` version duplicates present in the full-feature dependency graph.

## Breaking Changes

No breaking changes in this release.
