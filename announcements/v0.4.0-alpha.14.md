# reinhardt-web v0.4.0-alpha.14

## Highlights

This release significantly expands the form and routing infrastructure. Generated `page!` bindings now support all seven semantic input types — `search`, `tel`, `url`, `email`, `password`, `color`, and `range` — reusing a shared classifier that keeps browser and native behavior aligned while preserving focus and DOM state during signal updates. Building on this, ClientForm and ModelForm now share a common typed field-binding layer: form resets synchronize runtime state with mounted DOM controls in a single batched operation, overlapping submissions are guarded against stale completions, and structured server errors route through one unified form error lifecycle.

Forms take a major step toward target-neutrality: `ModelForm` contracts can now be generated without requiring a WASM shadow model, sharing payload, schema, and validation metadata across native and WASM targets while keeping ORM-specific behavior native-only. Complementing this, `server_fn`, `ClientForm`, and `ModelForm` gain a unified `ServerMutation<Input, Output>` lifecycle for pending state, typed results, structured errors, and redirects, working consistently across SSR and WASM.

Database error handling improves with backend-neutral constraint metadata on `DatabaseError`, letting generated forms map constraint violations (unique, not-null, foreign key, check) to precise field- or form-level errors without parsing driver-specific text.

Routing also matures: `UnifiedRouter` becomes a single non-generic public type across native and WASM targets, and a new asynchronous navigation-guard contract (`NavigationContext`, `NavigationDecision`, `NavigationGuardError`) coordinates authentication checks before loaders and commits across SSR, hydration, SPA navigation, and history traversal.

Numerous fixes address range/password/text input normalization, hydration reconciliation, and native fallback sanitization, along with a fix restoring upload metadata in model form test fixtures and generated migration source versioning for safer, non-exhaustive framework types.
