# reinhardt-web v0.4.0-alpha.3

## Highlights

Route macros now support raw `Request` parameters alongside typed extractors. Previously, mixing a raw `Request` argument with extractors like `Path` or `Json` in a single handler signature would fail during codegen, since the macro only recognized known typed extractor patterns. Handlers can now declare the raw request in any position relative to extractors and injected values, with the request passed through only after all typed extractors have finished borrowing it — preserving existing extraction and dependency-injection semantics. Several follow-up fixes hardened this feature, ensuring the generated request bindings are hygienic and correctly isolated even when arguments are aliased or renamed.

Static file serving is more robust when using `collectstatic` with content-hashed filenames. Source templates that reference stable, unhashed asset paths (e.g. `/static/vendor/unocss-runtime.js`) previously received a 404 because the configured static mount looked up the exact path instead of consulting the `manifest.json` alias table. The static command and manifest-alias handling now resolve these stable paths to their fingerprinted equivalents without affecting SPA fallback behavior, and this resolution is covered by new command-level and HTTP integration tests.

Session storage also gets a consistency fix: `DatabaseSessionBackend::load` and `exists` now use the same injected ORM connection capability as `save` and `delete`, instead of falling back to a separately resolved global connection. This ensures all four session operations consistently share the backend's registered connection owner, verified by a new SQLite lifecycle regression test.

## Breaking Changes

No breaking changes in this release.
