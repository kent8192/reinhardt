# reinhardt-web v0.4.0-alpha.6

## Highlights

This release delivers a major expansion of the ORM and forms layers. Model-backed forms can now be generated directly from `#[model(form = true)]` declarations, producing typed, policy-aware form schemas that persist through an async, caller-owned `OrmExecutor` with structured errors and transaction support — replacing the old synchronous `ModelForm` contract entirely. Alongside this, the query layer gains a substantial set of typed capabilities: a streaming `QuerySet` iterator for large result sets, transaction-safe `select_for_update()` row locking, `dates`/`datetimes` projections, backend-aware `explain`, and typed retrieval helpers (`latest`, `earliest`, `in_bulk`, etc.). Manager `get_or_create`/`update_or_create` now use typed, compile-time-checked field builders instead of stringly-typed maps.

On the tooling side, this release adds an ORM-aware Rust management shell (`manage shell`), a Django-compatible `inspectdb` command, `squashmigrations` for safely collapsing migration history, and new `showmigrations`/`sqlmigrate` visibility commands plus `dbshell` for launching native database clients. Native PostgreSQL `pgvector` support lands with HNSW/IVFFlat indexes and typed distance queries.

On the frontend side, Pages gains typed custom event payloads (`CustomEvent<T>`) for the `page!` DSL and a redesigned, app-scoped Query Client V2 with typed query families, SSR hydration, and centralized invalidation/polling — replacing the previous key/handle-based query API.

This release also includes an extensive series of correctness fixes across model forms, migrations (squash range/dependency handling), datetime/timezone handling in PostgreSQL/MySQL, and manager primary-key encoding, plus numerous CI stabilization and release-recovery fixes following a partial `0.4.0-alpha.5` publish.
