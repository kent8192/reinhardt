# reinhardt-web v0.4.0-alpha.8

## Highlights

This release delivers a major correctness and security milestone for the ORM and views layers. The centerpiece is a new request-scoped `QuerySetProvider` contract for `ModelViewSet` (#6093), which lets applications compose organization- or authorization-derived scopes with custom manager predicates and execute them through SQL via the configured `Session` pool, instead of loading entire tables and filtering in memory. `create` remains provider-free with PK-only refresh, and registering a provider without a database pool now fails closed for safety.

Building on that foundation, a long series of ORM hardening fixes closes edge cases uncovered during the request-scoping review: row-level locks are now applied correctly to scoped mutations and subqueries (including backend-specific handling for MySQL's nullable-relation and lock-target restrictions), typed field metadata and primary-key types are preserved through scoped reads/writes, composite and temporal primary keys are correctly versioned and displayed, and offset-free ISO timestamps decode reliably. Prefetch-only querysets and derived-source session queries are also now supported.

On the security side, the optional `commands` shell evaluator is upgraded to `evcxr 0.22.0` (#6121), removing the unmaintained `json` crate flagged by `RUSTSEC-2022-0081` in favor of `serde_json`, with no change to the evaluator API used by Reinhardt.

Finally, several CI/documentation fixes stabilize the release pipeline itself: breaking-change announcements now use the workflow token instead of a repository PAT (#6087), noisy code-scanning workflows are removed in favor of the deterministic `cargo-deny` audit (#6090), rustdoc link targets are corrected, and the interactive shell E2E test is given an adequate evaluator bootstrap timeout (#6126).

## Breaking Changes

No breaking changes in this release.
