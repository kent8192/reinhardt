# reinhardt-web v0.4.0-alpha.9

## Highlights

This release focuses on hardening query and serializer correctness while shoring up the framework's documented security posture. On the ORM side, scoped querysets now stay fail-closed: constraints are preserved across related fields, manager `HAVING` predicates, and correlated outer references, preventing scoped queries from unintentionally widening their result sets. Delete and update operations also reject tautological `WHERE` clauses (including empty `NOT IN` conditions), closing off a class of accidental full-table mutations, and legacy `Q` filters are now parameterized to avoid unsafe query construction.

Serializers gain more predictable error handling: custom field error messages are now preserved even when required JSON keys are omitted, and field structs with error messages remain constructible in more cases. The admin interface correctly converts the newer `FilterValue` temporal and decimal variants, and views now skip unnecessary refresh queries for unassigned string primary keys, avoiding spurious post-create errors.

On the infrastructure side, the Azure static files backend has been replaced to remove a legacy, insecure SDK dependency, and blob deletion is now idempotent for already-missing blobs. CI gains a fix for `zerovec-derive` patch duplication issues.

Alongside these fixes, this release includes an extensive expansion of the security documentation, formally defining framework trust boundaries — covering data/identity, request surface, UI/transport, runtime/operations, encryption policy, auth, vault, websockets, secrets, CSRF, and GraphQL/gRPC transport — clarifying which security guarantees are framework-enforced versus caller-enforced.

## Breaking Changes

No breaking changes in this release.
