# Migrating model forms to 0.4.0

Reinhardt 0.4.0 replaces hand-written `FormModel` metadata and synchronous
model saving with an opt-in generated bridge, typed payloads, explicit
create/update construction, and caller-owned asynchronous persistence.

## Opt in at the model

Model-form generation is no longer implied by implementing a separate trait.
Enable it explicitly on each supported model:

```rust
#[model(app_label = "polls", form = true)]
struct Question {
    #[field(primary_key = true)]
    id: Option<i64>,
    #[field(max_length = 200)]
    text: String,
}
```

`form = true` generates `QuestionFormSchema`,
`QuestionModelFormData<P>`, and the native `FormModel` bridge. A model without
this opt-in has no generated model-form symbols.

Generated validation is declared separately from database metadata:

```rust
fn validate_cluster<P: ModelFormPolicy>(
    cleaned: &CleanedClusterModelFormData<P>,
) -> Result<(), ValidationErrors> {
    // Return field errors or `_all` errors for cross-field failures.
    Ok(())
}

#[model(app_label = "clusters", form = true)]
#[form(validate = validate_cluster)]
struct Cluster {
    #[field(primary_key = true)]
    id: Option<i64>,
    #[field(editable = false)]
    organization_id: i64,
    #[field(min_length = 1, max_length = 63)]
    #[form(trim)]
    name: String,
    #[field(url = true, max_length = 2048)]
    #[form(trim)]
    api_url: String,
}
```

`#[field(...)]` remains database and model metadata. Use
`#[form(validate = path)]` for one synchronous cross-field validator and
`#[form(trim)]` for generated text, email, or URL normalization.

The direct before-and-after persistence migration is:

```rust
// Before: hand-written FormModel and synchronous save.
impl FormModel for Question {
    fn save(&mut self) -> Result<(), String> {
        Err("a synchronous ORM save cannot await the database".to_owned())
    }
}
```

```rust
// After: generated bridge and caller-owned async persistence.
#[model(app_label = "polls", form = true)]
struct Question {
    #[field(primary_key = true)]
    id: Option<i64>,
    #[field(max_length = 200)]
    text: String,
}

let saved = form.save(executor).await?;
```

Remove manual implementations of the old field-name, field-type, getter,
setter, validation, and synchronous save methods. The model macro now supplies
the bridge from the model definition and field attributes.

## Replace builders with generated payloads

`ModelFormBuilder`, `ModelFormConfig`, and `FieldType` have been removed.
Define public field selection in the Pages `form!` declaration or with a
`ModelFormPolicy`, then construct the generated payload:

```rust
use reinhardt::core::model_form::ModelFormPolicy;
use reinhardt::forms::ModelForm;

struct PublicQuestionFields;

impl ModelFormPolicy for PublicQuestionFields {
    fn allows(field: &str) -> bool {
        field == "text"
    }
}

let mut payload = QuestionModelFormData::<PublicQuestionFields>::empty();
payload.set_text("What should we build next?".to_owned());
let mut form = ModelForm::<Question, PublicQuestionFields>::from_payload(payload);
```

Known wire fields denied by the policy are rejected server-side with
`ModelFormError::ForbiddenInput`; hiding a field in HTML is not sufficient.
Trusted server code may call the generated typed setter for an excluded
editable value after authentication or authorization has resolved it.

## Validate generated payloads at the server boundary

Clients submit raw `ClusterModelFormData<P>` values. Server handlers must
consume the payload with `clean_and_validate()` even when Pages already ran
the same pipeline in the browser. The result is a generated cleaned payload;
cleaned payloads do not implement `Deserialize` and therefore cannot be
supplied by an untrusted client.

Run request- or database-dependent validation explicitly after synchronous
cleaning, then supply server-owned values through the generated typed context:

```rust
use reinhardt_core::model_form::ModelFormValidatingPayload;

let cleaned = payload.clean_and_validate()?;
ensure_cluster_name_available(&cleaned).await?;
let cluster = cleaned.into_model(
    ClusterModelFormServerContext::new().organization_id(organization_id),
)?;
```

The context's typestate prevents `into_model` from being called until every
required server-owned value is present. For an update, apply only the cleaned
public fields; primary keys and server-owned fields remain unchanged:

```rust
use reinhardt_core::model_form::ModelFormUpdatingPayload;

let cleaned = payload.clean_and_validate_for_update(&existing)?;
ensure_cluster_name_available(&cleaned).await?;
let updated = cleaned.apply_to(existing)?;
```

`clean_and_validate()` is the strict create boundary and reports omitted
required public fields before the create callback runs. For updates,
`ModelFormUpdatingPayload::clean_and_validate_for_update(self, &existing)`
merges omitted values from the existing model while running field validation
and synchronous `#[form(validate = path)]` validation. It returns a partial
cleaned payload, so `apply_to(existing)` still preserves omitted fields.
An explicitly supplied nullable `null` remains a clear operation.

Async validators are an application extension point rather than generated
model metadata. Keep them between cleaning and construction so they receive
normalized values. Persistence and database-error mapping remain the boundary
tracked by [#6222](https://github.com/kent8192/reinhardt-web/issues/6222).

## Preserve intentional trimming

Generated text, email, and URL fields no longer trim by default. Add
`#[form(trim)]` to each generated field that previously depended on implicit
trimming. Applications that treat leading or trailing whitespace as data make
no change.

This migration affects only model-generated form fields. The defaults of
manually constructed `CharField`, `EmailField`, and `URLField` values are
unchanged.

## Select create or update explicitly

Use `from_payload` for a new instance:

```rust
let mut form = ModelForm::<Question, PublicQuestionFields>::from_payload(payload);
let saved = form.save(executor).await?;
```

Use `from_payload_and_instance` for an existing instance:

```rust
let mut form = ModelForm::<Question, PublicQuestionFields>::from_payload_and_instance(
    payload,
    existing_question,
);
let saved = form.save(executor).await?;
```

The constructor records insert or update intent. Reinhardt does not query for
existence or infer intent from a primary-key sentinel.

## Replace `commit = false`

Use `build_instance()` when validation and construction must finish without a
database write:

```rust
let candidate = form.build_instance()?;
```

`build_instance()` is database-free and caches the validated candidate.
Repeated calls and persistence retries reuse it. A failed save retains both
the candidate and the original instance, so the form remains retryable.

The returned candidate is a clone of the cached candidate. Mutations made to
that clone after `build_instance()` do not pass through form validation;
validating or persisting those caller-owned mutations is the caller's
responsibility.

For creation, every required excluded or hidden value must be resolvable before
construction. Use a declared model default, a supported automatic construction
path, or a trusted typed setter for an excluded editable field. An ordinary
unresolved required field now returns
`ModelFormError::MissingModelField` instead of receiving a synthesized empty
value. Updates preserve omitted values from the existing instance.

Nullable model fields now distinguish an explicit clear from omission.
Browser-side clearing supplies JSON `null`, while clearing a non-nullable
blank/defaulted control omits the field. `DateTime<Utc>` and
`NaiveDateTime` also have separate generated kinds: offset-free browser
`datetime-local` input is interpreted as UTC for `DateTime<Utc>` and is kept
offset-free for `NaiveDateTime`.

## Pass an executor to every save

`ModelForm::save` and generated `FormModel::save` are asynchronous:

```rust
let saved = form.save(&mut connection).await?;
```

Pass the transaction executor from `atomic` when the save belongs to a larger
unit of work:

```rust
connection
    .atomic(async |transaction| {
        let saved = form.save(transaction).await?;
        update_search_index(transaction, &saved).await?;
        Ok(())
    })
    .await?;
```

The executor is owned by the caller. `ModelForm` does not open, commit, or
close a connection.

## Migrate formsets to async save

Formset saves now accept the same executor and must be awaited:

```rust
// Before
let saved = formset.save()?;

// After
let saved = formset.save(executor).await?;
```

Before persistence, `ModelFormSet` builds every candidate. It saves in form
order and stops at the first persistence error. Untouched create-mode extra
forms do not participate in cardinality, preflight, or persistence; supplied
input and forbidden wire input still make an extra a candidate. Populate an
extra through `forms_mut` with `ModelForm::set_field_value`, or replace its data
with a payload created by `ModelForm::from_payload`.

`ModelFormSetConfig` and `AdvancedModelFormSet` both enforce `min_num` and
`max_num` against submission candidates. Use `AdvancedModelFormSet` when forms
must be added incrementally with `add_form`. Both types check cardinality first,
then validate and build every candidate before the first write. Use one
transaction executor when all saved rows must commit or roll back together.

Inline formsets also save asynchronously. Parent persistence, assignment of
the saved parent key to child payloads, and child persistence all use the
caller-provided executor. Replace ambiguous parent construction with
`InlineFormSet::for_create` or `InlineFormSet::for_update`. This distinction is
required for assigned primary keys such as UUIDs. The legacy
`InlineFormSet::new` retains its primary-key-presence heuristic for source
compatibility and cannot represent assigned-key creation.

## Handle structured errors

The old string persistence error has been replaced by `ModelFormError`.
Database failures retain their structured `DatabaseError`:

```rust
match form.save(executor).await {
    Ok(saved) => use_saved_question(saved),
    Err(error) => {
        if let Some(database) = error.database_error() {
            handle_database_kind(database.kind());
        } else {
            handle_validation_error(error);
        }
    }
}
```

Relevant variants are:

- `ForbiddenInput` for a known field rejected by the public policy.
- `FieldValidation` for field cleaning failures.
- `MissingModelField` for an unresolved required model field.
- `ModelValidation` for candidate-level validation failures.
- `Persistence` when the database rejected the write.
- `PersistenceAfterCreate` when insertion succeeded but hydration failed.
- `TransactionOutcomePending` while a caller-owned transaction has not
  finalized the prior write.

Do not retry `PersistenceAfterCreate` as another create because the row already
exists; reload it before attempting an update. `database_error()` returns the
retained `DatabaseError` for both persistence variants, so do not flatten them
into strings when application logic needs to distinguish unique, foreign-key,
connection, or transaction failures.

## Update Pages `form!`

Model-backed Pages forms use a bracketed allowlist or denylist and submit one
payload:

```rust
let form = form! {
    name: QuestionForm,
    model: Question,
	policy: PublicQuestionFields,
    fields: [text],
    server_fn: save_question,
    overrides: {
        text: {
            widget: TextArea,
            label: "Question",
        },
    },
};
```

The server function names the policy it enforces and repeats validation:

```rust
async fn save_question(
    payload: QuestionModelFormData<PublicQuestionFields>,
) -> Result<(), ServerFnError> {
    let cleaned = payload.clean_and_validate()?;
    let question = cleaned.into_model()?;
    persist_question(question).await
}
```

The `form!` macro is still an expression macro. Its form-specific policy and
data alias are internal to the expression; there is no caller-visible
`QuestionFormPolicy` or `QuestionFormData` alias to import.

Prefer `fields` when possible. With `exclude`, any future editable model field
not present in the denylist is automatically added to the public form.
Ordinary explicit forms keep braced `fields: { ... }` and their existing
positional server-function arguments.

For a model form that selects a `File` or `Image` field, switch to an explicit
`fields: [...]` selection and a direct typed multipart server function. Its
client-visible arguments must have the same model-field names, order, and
count as the selection; use `UploadedFile` or `Option<UploadedFile>` for file
arguments. `exclude` and `ambient_arguments` are not supported in model-backed
forms; ordinary forms may still use `ambient_arguments` for non-field values.
Existing JSON model forms still call a `#[server_fn(model_form = true)]`
endpoint with one generated payload and keep their existing `fields` or
`exclude` behavior, but cannot submit file fields.
