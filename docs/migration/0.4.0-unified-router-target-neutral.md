# Migrating UnifiedRouter to 0.4.0

This is a breaking change within the 0.4.0 alpha line.

## Summary

Issue [#6224](https://github.com/kent8192/reinhardt-web/issues/6224) makes
`UnifiedRouter` one non-generic public type on native and WASM. Native client
state is thread-affine, so storing it in the native router made applications
that declare client routes return a different type from their WASM builds.

`UnifiedRouter` now stores only the route representation active for its target:
native stores server and protocol state, while WASM stores client routing and
navigation state.

## Return types

Replace cfg-selected aliases and `UnifiedRouter<ClientRouter>` return types
with plain `UnifiedRouter`. The public type is non-generic on both targets.

## Inactive builders

Both builders remain available with `client-router`, so shared declarations can
continue to call `.server(...)` and `.client(...)`.

- Native `.client(...)` type-checks its `FnOnce(ClientRouter) -> ClientRouter`
  closure but does not invoke it or retain client state.
- WASM `.server(...)` type-checks its `FnOnce(ServerRouter) -> ServerRouter`
  closure but does not invoke it or retain server state.

Inactive closures must not perform required side effects. Put client setup in
the active WASM path, and keep server setup in the active native path.

## Removed native APIs

Native `UnifiedRouter` no longer stores a client router. Remove uses of these
native APIs:

- `client_ref`
- `client_mut`
- `into_client`
- `into_parts`
- client-returning `register_globally`

Construct a `ClientRouter` directly when native test code needs client route
inspection or reversal.

## Testing client routes

Client route tests on native must create the client router in a reactive scope:

```rust
use reinhardt_core::reactive::ReactiveScope;
use reinhardt_urls::routers::ClientRouter;

ReactiveScope::run(|| {
    let router = configure_client_routes(ClientRouter::new());
    assert_eq!(router.reverse("dashboard:home", &[]).unwrap(), "/");
});
```

This executes client route construction instead of relying on native
`UnifiedRouter::client(...)`, which is intentionally inert.

## Before and after

```rust
// Before
#[cfg(server)]
type AppRouter = UnifiedRouter<ClientRouter>;

#[cfg(not(server))]
type AppRouter = UnifiedRouter;

pub fn url_patterns() -> AppRouter {
    // ...
}

// After
pub fn url_patterns() -> UnifiedRouter {
    // ...
}
```

Keep cfg gates for target-only imports, handlers, and statements. The common
router return type no longer needs a cfg-selected alias.

## Validation

Validate the supported configurations after migrating:

```bash
# Native without the server feature
cargo check -p reinhardt-web --no-default-features --features client-router

# Native with the server feature
cargo check -p reinhardt-web --no-default-features --features client-router,server

# WASM client-routing regression
cargo check --offline --target wasm32-unknown-unknown -p reinhardt-urls \
  --features wasm-diag-test --test unified_router_target_parity_test
```
